# M3 independent browser foundation

This increment implements the first browser infrastructure against the existing
M0/M1 production ABI. **M3 is not complete and Tapweave is not playable.** M2
production advance/snapshot/pause remain unsupported; the browser keeps Play
disabled. See the [approved M3 plan](m3-plan.md).

## Implemented

- Separate Node 24 browser package with exact fflate 0.8.3 / Playwright Test 1.63.0
  lockfile, framework-free UI, static build and loopback development server.
- A production-only WASM entrypoint without test trace exports.
- One generated JavaScript ABI reader/writer shared by browser and TypeScript
  consumers, including checked spans and named bootstrap transport offsets.
- Real ABI map preparation and owned descriptor copies, typed errors, lossless
  handles, memory-view reacquisition and explicit release/disposal.
- Local archive/loose-file loading and difficulty selection. ZIP validation covers
  paths, ambiguity, structure/ranges, compression support, quotas and CRC.
- Transactional replacement and asynchronous generation cancellation. Failed
  replacement preserves the previous valid map and its asset scope. Decoded music
  is cached across difficulty changes within a source and released with the scope.
- An independent audio anchor and execution service for explicit test events,
  voice/ramp/epoch cleanup, late-event policy and bounded queues.
- An independent physical-input aggregation/buffering service with receipt-time
  transform snapshots, retained failed submissions and release-all behavior.
- An Odin playfield transform and exact native/WASM local test transport.
- A shared round-trip float marshaler for simulation/presentation test evidence.
- Diagnostics export, responsive layout and a browser CI job.

The input/audio services are not wired into gameplay. Their explicit JS fixtures
are not production protocol definitions or upstream observations. Source-specific
sample selection, loops/ramps and object presentation remain Odin responsibilities.
The initial transform does not yet expose a production presentation capability.

## Verification

Executed locally on macOS arm64 with Node 24.13.0 and the repository-pinned Odin:

- `npm --prefix engine test`: source hash verification, generated binding checks,
  allocation-tracked Odin tests, C ABI tests and native/WASM decoder, geometry,
  preparation, M2 primitive and viewport tests.
- `npm --prefix platform/browser-js test`: 20 passing archive, ABI, selection, input and
  audio-clock/executor contract tests against real WASM or explicit fake services.
- Browser static assembly and three Chromium Playwright integration scenarios:
  real preparation/failed replacement, archive difficulty selection at narrow
  viewport, unsafe archive rejection and diagnostics download.
- Desktop/narrow screenshots inspected locally. Images and reports are ignored
  artifacts, not committed assets.

The full Playwright run attempted nine scenarios. Chromium passed; Firefox and
WebKit could not launch because the pinned executables were absent. Browser
installation attempts timed out repeatedly; no successful Firefox/WebKit/Safari
validation is implied. CI configuration is added but has not been run here.

No new upstream comparison or H11 run was executed. Local parity and mocked audio
are not upstream acceptance. A12 has an independent transform subset only; A12,
A21 and A22 remain open.

## Remaining gates and limitations

Full M2 integration, readonly object snapshots and durable audio output are
prerequisites for playable sessions. M3 still requires pinned H11/A22 adapters,
object animation, static meshes/atlas, WebGL2 protocols/execution, real input
listeners, music transport, integrated pause/resume/focus/context recovery and
final results. No render protocol or gameplay capability is advertised.

The shell deliberately reports missing/undecodable music while allowing map
inspection. Production start remains unavailable. Default assets and hitsound
availability submission are not implemented. ZIP64, encryption, multi-disk,
unsupported compression and non-UTF8 non-ASCII names reject explicitly.

Browser decodeAudioData cannot be cancelled and its internal peak allocation is
not bounded by a post-decode cache-size check. The actual size is checked before
retention; broader media resource hardening remains open. No performance baseline,
p99 approval, real audio output, hardware input release matrix, four-session
browser sharing or long browser soak is claimed.

The browser package guide contains reproduction commands and exact resource
limits. Full remaining work stays recorded in the approved plan, with M2 gates
preserved rather than bypassed by a browser-side simulation.
